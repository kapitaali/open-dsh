# RR-W22 — Connection profiles for the dsh fork

**Date:** 2026-11-14 · **Branch:** `connection-profiles` · **Base:** `master` (release 0.2.2-rc.3)
**Status:** implemented, gates green, uncommitted at time of writing

---

## 1. What this is

A fork feature for the DeepSeek Harness: **connection profiles**. The default profile keeps the
default DeepSeek connection; a custom profile can be given an API endpoint URL and an API key
and connects there instead.

The default profile is untouched — with no patch row, the `llm-deepseek` plugin still falls back
to `$DEEPSEEK_BASE_URL` / `DEEPSEEK_API_KEY` / `https://api.deepseek.com/anthropic`. A custom
connection is applied by writing the `llm-deepseek` row's `config` (`baseURL` + `apiKeyEnv`)
into that profile's own `cordis.patch.yml`.

Plans of record: `design/W22-DSH-CONNECTIONS-20261114.md`, `design/W22-DSH-ADAPTER-20261114.md`.

## 2. What was built

### 2.1 New package — `packages/util/connection-store/`

`@deepseek-ai/dsh-connection-store` (kind `package-reference`):

- `$DSH_HOME/connections.yaml` — a versioned YAML document holding named connections
  (`name`, `baseURL`, `apiKeyEnv`). No secret value lives in it.
- Strict parse: a malformed document, unknown version, duplicate name, or a field outside its
  grammar throws rather than being skipped. An absent document is an empty store.
- `storeConnectionKey` / `removeConnectionKey` — edit the credential store's `refs` section
  with the same comment-preserving, locked, atomic write the credentials provider uses
  (mode `0600`, dir `0700`).
- Registered in `tsconfig.host.json`, `apps/cli/tsconfig.json`, `tsconfig.base.json`
  (via `pnpm run gen-tsconfig-paths`), and `packages/util/README.md`.

### 2.2 CLI — `dsh connection`

| Command | Effect |
|---|---|
| `dsh connection add <name> --url <url> --key <key>` | Save a connection + its API key |
| `dsh connection use <profile> <name>` | Apply a connection to a profile's patch |
| `dsh connection list` | List saved connections |
| `dsh connection show <name>` | Show one connection |
| `dsh connection remove <name>` | Remove a connection + its key |
| `dsh connection create <profile> --url <url> --key <key>` | Create a profile with a connection |

Wiring: `ConnectionInvocation` + commander subcommand in `apps/cli/src/args.ts`, dispatch in
`apps/cli/src/bin.ts`, examples in the launcher help. `apps/cli/src/connection.ts` reproduces
the config-editor's patch write (comments and `!!js` preserved, atomic `0600`).

### 2.3 Docs

`docs/cli-help.md` / `.zh.md` regenerated with a `## dsh connection` section
(`scripts/gen-cli-help.ts` now visits the subcommand; its spec updated).

## 5. Limitations and open questions

- **No npm distribution yet.** The feature lives in the fork's tree; the release path (npm
  package, tarball, or run-from-source) is an owner decision.
- **No settings UI.** Connections are CLI-only so far; the Web Settings page does not manage
  them.
- **`--key` on the command line** is visible in shell history. A prompt-based input (like the
  Models page) is the alternative.
- **The connection document does not preserve hand-written comments** across a write; it is
  machine-managed.
- **No runtime reader.** The harness runtime resolves the resulting `llm-deepseek` config; it
  never reads `connections.yaml`.
- **W22 adapter (ctxvm trace capture) is design-only** in this commit; only the connection
  feature is implemented.
